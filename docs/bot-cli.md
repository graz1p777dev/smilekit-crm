# Отладчик WhatsApp-бота

Два окна в терминале: в одном вы переписываетесь с ботом, во втором видно
всё, что он при этом делает — какое правило сработало и почему, какой шаблон
выбран, что ушло в ИИ и что он вернул, какие метки поставлены в базе и что
ушло бы в WhatsApp.

Отвечает тот самый бот, что отвечает клиентам: `src/lib/greenapi/bot-reply.ts`
и `src/lib/greenapi/followup-scheduler.ts`, без копий и упрощений.

## Запуск

Из основной папки проекта (там, где привязан Railway):

```bash
npm run bot:cli     # окно 1 — переписка
npm run bot:debug   # окно 2 — отладка
```

Первый запуск сам создаёт окружение Python в `tools/bot-cli/.venv` и ставит
`rich` (в git ничего из этого не попадает). Ключи берутся из Railway —
`bot:cli` поднимается через `railway run --service smilekit-crm`.

Порядок окон не важен: окно отладки дождётся сеанса и догонит всё, что уже
было. Оба окна находят сеанс сами — сервер слушает только `127.0.0.1` и
пишет порт в `tools/bot-cli/.session.json`.

## Команды окна переписки

| Команда | Что делает |
|---|---|
| `<текст>` | сообщение от клиента |
| `/reset` | начать с нуля: новый служебный чат, бот видит совершенно нового клиента |
| `/time +2h` | перемотать время назад (`+30m`, `+2h`, `+1d`) и прогнать проверку дожимов |
| `/state` | метки `ga:claim:*`, этап сделки, кто ведёт чат, сколько сообщений |
| `/manager <текст>` | сообщение «от менеджера» — проверить, что бот замолкает |
| `/photo [url]` | картинка-чек (без ссылки берётся тестовая картинка бота) |
| `/voice <текст>` | голосовое; текст — это его расшифровка |
| `/help` | справка |
| `/quit` | выход, с предложением удалить следы служебного чата |

## Почему это не трогает клиентов

1. **Только служебный чат.** Id вида `lab-cli-<метка времени>` генерируется
   самим отладчиком; реального номера там быть не может. Такие чаты не
   попадают ни в рассылки, ни в аналитику.
2. **Отправка физически отключена.** Модуль `src/lib/greenapi/client.ts`
   подменяется заглушкой на уровне загрузчика модулей
   (`scripts/bot-cli-loader.mjs`): ни одна функция отправки не ходит в сеть,
   любая попытка печатается в окне отладки красной панелью. Если подмена не
   сработала, ядро это замечает по метке `__BOT_CLI_STUB__` и **не
   запускается вообще**.
3. **Режим `dryRun`.** Сделки, заказы, остатки на складе, группы доставки и
   внешние вебхуки не трогаются.
4. **Планировщики не поднимаются.** Проверка дожимов вызывается напрямую по
   `/time`, фоновых таймеров отладчик не запускает.
5. **Следы убираются.** `/quit` предлагает удалить служебный чат, `/reset`
   удаляет предыдущий, а старт нового сеанса подметает всё, что осталось от
   сеансов, закрытых через Ctrl+C.

Всё это закрыто тестами: `src/lib/greenapi/client-stub.test.ts` (заглушка
покрывает весь клиент и не ходит в сеть) и `src/lib/greenapi/trace.test.ts`
(без отладчика трассировка молчит и ничего не считает).

## Что стоит знать при чтении отладки

- Дожим при молчании в проде **выключен** флагом `IDLE_NUDGES_ENABLED` в
  `followup-scheduler.ts`. По `/time` отладчик всё равно показывает, что
  было бы, отдельной жёлтой панелью «в проде выключено».
- Строки `Можно ли писать в чат`, `Метка-защёлка в базе` и `Контекст` —
  фоновые, печатаются одной тусклой строкой. Остальное — панелями.
- `Ушло бы в WhatsApp` — это ответ бота (в дебюте видно и то, что он ушёл бы
  голосовым файлом). `Отправка заблокирована` — попытка достучаться до Green
  API, пойманная заглушкой; в нормальном сеансе её быть не должно.
